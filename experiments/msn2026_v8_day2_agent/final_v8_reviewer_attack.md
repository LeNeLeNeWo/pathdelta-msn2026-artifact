# Hostile MSN reviewer attack on PathDelta-Agent v8

This review evaluates the current pilot package, not a nonexistent formal result.

1. **“Change Envelope is preserve-everything-except-target.”** At the semantic level, yes: the frame is the observed target complement. The nontrivial candidate contribution would be grounding the target, enumerating the relevant behavior universe, separating attributes of the same FEC, computing external dependency sharing, authorizing footprint, and compiling relations. The paper has not compared against a plain preserve-all-observed-FEC baseline, so it cannot yet show that the full abstraction adds value beyond that slogan.

2. **“Handwritten intent rules hide the complexity.”** The v2 inference path has zero family dispatch branches, expected patch templates, or strategy labels, which is a meaningful code property. But typed intent change atoms and the finite BGP behavior adapter are manually designed. Natural-language normalization error and relation selection have not been evaluated. Generality is therefore partial, not proved by the branch count.

3. **“Rela already has frame relations.”** Correct. Preserve/replace/add/remove are Rela capabilities, not PathDelta contributions. The possible increment is automatically deriving intent-relative target/complement obligations from brownfield pre-state and mapping independent FEC paths to them. One integration example cannot establish novelty or robustness of that compiler.

4. **“Batfish differential analysis already exists; this is glue.”** Much of the current implementation is integration glue. The paper is viable only if envelope inference changes which differential questions must be asked and catches classes not captured by fixed reachability/scope checks. The current reachability-versus-path example motivates that distinction but does not establish a substantial system contribution.

5. **“Static write scope is enough.”** On the development taxonomy, write scope rejects over-broad/footprint edits but accepts all 18 goal-satisfying collateral candidates. This is suggestive, but the same authors designed those mutations. A stronger independent scope baseline and public/natural LLM failures are needed before dismissing this objection.

6. **“The Agent is not actually free.”** Raw traces show model-owned exact edits and no renderer. V2 accepts local, reuse, conformant, style-nonconformant, and direct-LLM safe classes. The pilot also fixed a closure rule that had implicitly forced a fork. Nevertheless, most alternatives are programmatic fixtures; independent alternatives per public intent are missing.

7. **“The iterative baseline is weak or outdated.”** A common harness implements retrieval, exact edits, syntax/goal feedback, retries, equal model/budgets, and raw traces. Only a one-case smoke exists, so strength has not been empirically demonstrated or compared to a faithful recent configuration-repair implementation. This objection stands.

8. **“Unsafe candidates are tailored to V5.”** This is the largest benchmark threat. Candidate generation is code-separated from inference and includes three direct-LLM candidates, but 54/57 candidates come from named A–I templates and the same repository/authorship. Perfect V5 separation increases, rather than decreases, suspicion. Independent authorship and naturally failed LLM candidates are mandatory.

9. **“False reject is hidden by a reject-everything system.”** V5 accepted 27/27 safe development candidates and five implementation classes, so it is not literally reject-all. The safe corpus is small/co-designed and lacks ambiguous or backend-incomplete alternatives; a 0% development false-reject rate is not credible population evidence.

10. **“Semantic preservation covers only a few FECs.”** Correct. The behavior universe is explicitly destination-sampled and every envelope records `universe_complete=false`. The current work can claim bounded verification over observed behavior only, not semantic preservation of the whole network.

11. **“Shared dependency inference will not generalize.”** The graph extractor handles route-map bindings, prefix/community lists, call, on-match continuation structure, nested/shared child policies, and multi-source pre-states. Cross-source inference found a real over-protection bug and was corrected. No independently labeled candidate experiment tests those non-shared-route-map patterns, so generalization remains partial.

12. **“Brownfield conformance is only a proxy.”** Correct. Naming, sequence, parameter-grid, reuse, motif, and AST-distance scores are automatic proxies. There is only an unpopulated blinded human-evaluation package. No operator-preference claim is allowed.

13. **“Dynamic validation is insufficient.”** Correct. The current v8 has an FRR syntax run and one Batfish/Rela integration; no stratified new Kathara dynamic sample was executed. Gate 6 fails.

14. **“Multi-protocol/multi-device claims exceed evidence.”** Multi-protocol claims are rejected. One source-conditioned multi-device pre-state is construction coverage, not outcome evidence. The scope must remain BGP Day-2 policy on FRR-like configurations.

15. **“Calling the system safe is an overclaim.”** Correct. Parser warning, incomplete FEC enumeration, model/environment mismatch, and dynamic convergence gaps remain. Use “bounded verified,” “envelope-compliant over extracted observations,” or “rejected an observed collateral relation,” never unqualified safe.

## Reviewer recommendation

Reject in current submission form. The mechanism is coherent and the motivating risk is credible, but the central same-LLM efficacy result is absent, the perfect verifier classification is vulnerable to benchmark co-design, and backend/dynamic coverage is far below a systems-paper bar. Invite resubmission only after preregistered independent data and paired agent evidence.
